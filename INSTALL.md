# Инструкция: установка, запуск и использование Domonap Telegram Bot

Бот управляет домофоном Domonap через Telegram — открывает двери, показывает список домофонов, присылает уведомления о входящих звонках. Работает автономно, без Home Assistant.

## 1. Требования

- Python **3.12+** (если запускаете без Docker)
- Docker и Docker Compose (рекомендуемый способ)
- Токен Telegram-бота от [@BotFather](https://t.me/BotFather)
- Ваш номер телефона, привязанный к аккаунту Domonap
- Свой Telegram user ID (узнать можно у [@userinfobot](https://t.me/userinfobot))

## 2. Получение кода

```bash
git clone <repo-url> domonap-telegram-bot
cd domonap-telegram-bot
```

## 3. Настройка `.env`

```bash
cp .env.example .env
```

Откройте `.env` и заполните переменные:

| Переменная | Что указать |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен, выданный @BotFather |
| `ALLOWED_TELEGRAM_USER_IDS` | Ваш Telegram user ID (и других доверенных людей) через запятую — кто сможет открывать двери |
| `ADMIN_TELEGRAM_USER_IDS` | Telegram user ID тех, кто может авторизовывать бота в Domonap |
| `DOMONAP_PHONE` | Номер телефона аккаунта Domonap (в международном формате) |
| `STORAGE_PATH` | Путь к файлу БД SQLite, по умолчанию `data/storage.db` — обычно не трогать |
| `LOG_LEVEL` | `INFO` по умолчанию, `DEBUG` для отладки |
| `CALL_WATCHER_ENABLED` | `true`, чтобы получать уведомления о входящих звонках |

⚠️ **Важно:** если оставить `ALLOWED_TELEGRAM_USER_IDS` пустым, бот будет открыт для **любого** пользователя Telegram, который его найдёт. Обязательно укажите свой ID перед запуском в продакшене.

Пример заполненного `.env`:
```env
TELEGRAM_BOT_TOKEN=123456789:AAExampleTokenFromBotFather
ALLOWED_TELEGRAM_USER_IDS=111111111,222222222
ADMIN_TELEGRAM_USER_IDS=111111111
DOMONAP_PHONE=+79991234567
STORAGE_PATH=data/storage.db
LOG_LEVEL=INFO
CALL_WATCHER_ENABLED=true
```

## 4. Запуск

### Вариант A — Docker (рекомендуется)

```bash
docker compose up --build -d
```

Проверить, что бот работает:
```bash
docker compose logs -f
```

Остановить:
```bash
docker compose down
```

Данные (токены, SQLite-база) сохраняются в папке `./data` на хосте — том смонтирован в `docker-compose.yml`, так что при пересборке контейнера ничего не теряется.

### Вариант B — без Docker

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python -m domonap_bot.main
```

Для остановки — `Ctrl+C`. Для постоянной работы на сервере лучше использовать systemd-сервис или screen/tmux, либо всё же Docker.

## 5. Первая авторизация в Domonap

Авторизация происходит через SMS-код от Domonap. Выполняет её пользователь из списка `ADMIN_TELEGRAM_USER_IDS`.

1. Откройте диалог с ботом в Telegram, отправьте `/start`.
2. Отправьте `/auth` — на телефон, указанный в `DOMONAP_PHONE`, придёт SMS-код (номер в ответе бота будет замаскирован).
3. Отправьте `/code <код_из_смс>`, например `/code 4821`. Сообщение с кодом бот автоматически удалит из чата в целях безопасности.
4. Отправьте `/status`, чтобы убедиться, что подключение установлено.

Токены сохраняются в SQLite (`data/storage.db`) и автоматически обновляются при истечении — повторная авторизация не требуется, пока не понадобится `/logout`.

## 6. Команды бота

| Команда | Кто может использовать | Что делает |
|---|---|---|
| `/start` | все разрешённые | Приветствие и список команд |
| `/status` | все разрешённые | Статус авторизации (без чувствительных данных) |
| `/doors` | все разрешённые | Список доступных дверей/домофонов |
| `/open` | все разрешённые | Интерактивный выбор и открытие двери |
| `/auth` | admin | Запрос SMS-кода от Domonap |
| `/code <code>` | admin | Подтверждение SMS-кода и сохранение токенов |
| `/logout` | admin | Сброс сохранённых токенов |

**Обычное использование:** отправляете `/open`, бот показывает кнопки с дверями — нажимаете нужную, дверь открывается.

## 7. Уведомления о входящих звонках

Если `CALL_WATCHER_ENABLED=true` (по умолчанию), бот сам следит за звонками в домофон и присылает всем из `ALLOWED_TELEGRAM_USER_IDS`:

- название/адрес двери;
- время звонка;
- фото/превью, если доступно;
- кнопку «Открыть» — открывает дверь одним нажатием;
- кнопку «Видео» — ссылка на видеопоток, если есть.

Механизм: сначала пробует держать real-time соединение через SignalR Notification Hub; если недоступно — переключается на polling лога звонков раз в 5 секунд, с автоматическим переподключением. Повторные уведомления по одному и тому же звонку не дублируются.

Отключить: `CALL_WATCHER_ENABLED=false` в `.env` и перезапустить бота.

## 8. Обновление и обслуживание

Обновить код и перезапустить:
```bash
git pull
docker compose up --build -d
```

Посмотреть логи:
```bash
docker compose logs -f --tail=100
```

Сбросить авторизацию (например, если сменился номер телефона): отправьте боту `/logout`, затем повторите шаги из раздела 5.

## 9. Частые проблемы

- **Бот не отвечает** — проверьте `docker compose logs`, скорее всего неверный `TELEGRAM_BOT_TOKEN`.
- **«Доступ запрещён»** — ваш Telegram ID не в `ALLOWED_TELEGRAM_USER_IDS`; узнайте свой ID через @userinfobot и добавьте в `.env`, перезапустите бота.
- **Не приходят уведомления о звонках** — проверьте `CALL_WATCHER_ENABLED=true` и что вы в `ALLOWED_TELEGRAM_USER_IDS`; посмотрите логи на предмет ошибок SignalR/polling.
- **`/open` не показывает двери** — не выполнена авторизация (`/auth` + `/code`) или истёк токен — проверьте `/status`.
